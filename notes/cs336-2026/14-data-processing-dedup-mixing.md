## Technical notes

Raw web pages, PDFs, and code repositories need task-dependent serialization. HTML extraction removes boilerplate but can lose structure; PDF parsing can scramble reading order, captions, mathematical symbols, and tables. Such corruption is not cosmetic: it alters the distribution of training tokens.

Filtering classifiers can select examples that resemble higher-quality target sets, but the definition of “quality” is itself an assumption. Exact deduplication hashes identical documents. Near-duplicate detection often compares sets of shingles with Jaccard similarity,

\[
J(A,B)=\frac{|A\cap B|}{|A\cup B|},
\]

then uses MinHash/LSH to find likely matches without all-pairs comparison. Data mixture weights and repeated epochs affect which material gets learned. Synthetic data generated by stronger models can make tasks cheap to produce while propagating teacher errors and biases.

## What matters for consider

Evaluation sets must be deduplicated against prompt templates, earlier tuning sets, and near-copy variants where possible. Rewording a worked example is not automatically a fresh held-out test. The candidates generated by a model also need diversity checks beyond distinct typography or vocabulary.

If consider eventually trains a judge on pairwise preferences, selecting “good-looking” labels risks teaching verbosity and consensus instead of truth. Prefer independently checked outcomes when feasible, and keep judge training separate from test labels.

## Proposed experiment

Build exact-hash and near-duplicate audits for the evaluation corpus; sample flagged and unflagged pairs for manual review. Run a candidate-diversity ablation: vary prompt instructions, sampling settings, and model families, then measure *distinct externally verified failure modes* as well as lexical differences.
